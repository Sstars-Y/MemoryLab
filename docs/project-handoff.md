## 2. 最终目标

MemoryLab 的最终目标是成为一个**本地优先、来源可核对、用户可控制的长期记忆聊天系统**，并能作为独立应用运行，也能在未来以版本化核心模块接入其他宿主。

最终系统需要同时满足以下能力：

### 2.1 完整保存

- 按人格、用户和会话隔离保存双方完整原话。
- 相同正文的多次真实发言保持为不同事件，不按正文合并。
- 用户消息先保存；助手完整回答生成成功后再一次性保存。
- 停止、失败或取消的助手草稿不进入正式记忆。
- 图片和语音保存原文件、稳定附件编号及独立识别结果。

### 2.2 可靠回忆

- 同时支持近期上下文、结构化筛选、全文检索和本地语义检索。
- 检索结果必须回查权威原消息，不能把摘要或向量近似结果直接当作事实。
- 回答时记录本轮实际提供给模型的历史来源。
- 区分用户原话、助手旧回答、媒体识别结果和模型整理摘要。
- 语义模型不可用时，原文、编号、时间和结构化查询仍然可用。

### 2.3 理解变化

- 保留原记录，通过修订记录错误纠正、状态变化和转写修正。
- 后续变化优先于旧状态，但旧记录仍可作为历史经过查看。
- 经历摘要必须关联原消息编号和来源版本，不能替代原文。

### 2.4 可控遗忘与恢复

- 用户只遗忘明确选择的消息及其直接派生内容。
- 删除后立即退出日常检索，并进入 7 天回收站。
- 支持到期前恢复、提前永久清理和到期自动清理。
- 生命周期状态独立于普通快照，防止旧快照或迟到后台任务复活已删除内容。

### 2.5 隐私和安全边界

- 默认只监听本机回环地址。
- 密钥只保存在进程内存，不进入数据库、日志、导出或快照。
- 人格目录中的 `users/` 永远不被程序枚举、读取、索引、哈希、导出或备份。
- 不自动读取 QQBot、其他程序或用户目录中的私有数据。
- 所有访问由宿主绑定 `persona_id`、`user_id`、`session_id` 和运行代号。

### 2.6 最终交付形态

- 可双击启动的独立本地网页应用。
- 可复用、版本化的 `memory_core` 核心包。
- 清晰的宿主适配接口，可在副本中安全接入 QQBot 等系统。
- 完整的自动化测试、规模测试、迁移说明、恢复说明和可审计验收证据。

运行环境、模型、测试证据和真实人格数据都位于项目自己的 `.local/`，该目录不进入 Git。

```text

├─ tmp/                               # 临时上传和子进程临时文件
├─ data/

│  └─ personas/<persona_id>/

│     ├─ lore/                        # 程序允许读取的人格扩展资料
│     ├─ users/                       # 用户手工文件，程序禁止读取
│     ├─ system.md                    # 编译后的人格提示
│     ├─ config/                      # 非密钥运行配置
│     ├─ data/memory/metadata.db      # 权威消息和状态数据库
│     ├─ data/media/images/           # 受管图片原文件
│     ├─ data/media/audio/            # 受管语音原文件
│     ├─ data/indexes/vectors/        # 可重建向量索引
│     ├─ exports/                     # 用户明确生成的范围导出
│     └─ backups/                     # 本人格一致性快照
├─ verification/                      # 合成验证和验收证据
└─ benchmarks/                        # 合成规模和性能报告
```

### 权威关系

- `metadata.db` 是消息、附件引用、修订和派生来源关系的权威库。
- 媒体目录中的原文件与数据库附件记录共同构成完整消息。
- `lifecycle/<persona_id>.db` 是删除、恢复和永久清理状态的最新权威来源。
- 向量索引、片段和经历摘要均为派生内容，可以重建，不能决定原文真假。
- `users/` 不属于程序记忆系统，不得自动同步到数据库或人格提示。

## 6. 当前记忆处理流程

```text
接收用户消息
   ↓
检查作用域、长度、幂等键和疑似凭据
   ↓
保存用户原文、全文索引、附件关系和后台任务
   ↓
查询近期上下文 + 精确全文 + 宽松全文 + 近期匹配 + 向量片段
   ↓
回查原消息、来源版本、修订和生命周期状态
   ↓
按预算构造本轮模型上下文并登记来源
   ↓
模型流式生成内存草稿
   ├─ 停止、失败、来源变化 → 丢弃草稿
   └─ 完整成功 → 再次校验并保存助手完整回答
   ↓
后台整理连续片段、向量和经历摘要
```

重要原则：

- 用户消息的保存不依赖模型回答是否成功。
- 助手流式草稿不是正式记忆。
- 自动召回默认查用户原话；只有问题明确询问助手过去说过什么时才以助手消息为主要候选。
- 向量命中只负责寻找候选，最终必须回查原消息。
- 纠正、删除或切换记录状态会提升 epoch，使迟到请求和后台任务拒绝提交。

## 7. 启动与开发

### 7.1 正常启动

首次或环境需要重建时运行：

```text
E:\MemoryLab\准备环境.cmd
```

启动应用：

```text
E:\MemoryLab\启动实验版.cmd
```

默认监听 `127.0.0.1:8765`。关闭网页不会自动停止服务，应使用网页中的退出入口或在启动控制台按 `Ctrl+C`。

### 7.2 模型配置

- 默认使用模拟模型，适合验证流程，不代表真实聊天质量。
- 远程地址、模型和非敏感参数可以持久化。
- API 密钥只在当前进程内存中保存，重启后需要重新填写。
- 不要从 `临时apikey.txt`、其他应用或系统目录自动读取密钥。
- 远程测试可能产生费用，必须得到用户明确授权。

### 7.3 本地语义模型

本地 BGE-M3 准备入口：

```powershell
.\.local\runtime\venv\Scripts\python.exe scripts\prepare_memory_lab.py --embedding --skip-sync
```

运行时只读取项目内已准备的模型，不应自动联网下载。embedding 不可用时，系统应降级到全文和结构化检索。

## 9. 当前已知限制

- 当前产品默认面向单机、单用户和一个默认人格；核心已有范围隔离，但多用户产品流程尚未完整开放。
- 尚未提供整个人格删除或清空入口。
- 尚未完成真人麦克风和人工听音验收。
- 个人最关心的 3–5 个长期记忆样例尚未由用户定义。
- 来源召回精度不是 100%，模型也可能不使用已提供的全部来源。
- 大规模语料由有限模板生成，不代表百万种不同语义。
- 尚未正式接入 QQBot、NapCat 或 Mofox。
- 当前锁定环境以 CPU 推理为准，未承诺 GPU 性能。

## 12. 完成定义

MemoryLab 达到最终目标，需要满足：

- 用户可以长期保存、搜索、核对、纠正、删除和恢复完整交流。
- 任一回忆都能展开到有权限读取的原消息或明确标记为无可靠来源。
- 摘要、embedding 或模型推断不会覆盖权威原文。
- 暂停保存、模型失败、程序重启和重复提交不会制造伪记录。
- 删除状态不会被旧任务、旧索引、旧导出或旧快照绕过。
- 密钥、`users/` 和其他人格数据不会泄露到模型上下文或产品文件。
- 独立应用可稳定运行，核心模块具备清晰版本和宿主接入边界。
- 自动化、规模验证、迁移和恢复文档能够让下一位开发者复现结论。
