# 长期记忆实验项目交接方案

> 版本：v0.5 · 日期：2026-11-13 · 状态：用户已确认首版方向；交接设计，未实施。
> 本文的目录、模块、接口和表是目标结构，不表示已经创建或实现。实验在独立项目目录进行，当前 QQBot 主项目保持原有运行方式。

## 1. 已确定的目标

让一个模型助手跨会话保留完整交流，能够回忆共同经历、核对原话、理解变化，并接受纠正和删除。

**已确认交付：方案1（可独立聊天的长期记忆应用）＋简单本地网页＋全新独立仓库。本机准备一次环境后，双击脚本启动并打开网页。** 不是只供其他程序调用的记忆服务，也不是训练新的基础模型；模型通过适配接口调用，长期记忆由应用管理。

- **双方每条消息均保存**：不按重要性自动丢弃，不因正文相同而合并两次发言；摘要在原文之上整理，不替代原文。正常完成的多次回答分别保留；主动停止的未完成回答作为临时草稿丢弃，不进入历史与回忆。
- **图片与语音作为消息附件保存**：聊天记录显示 `【图片】@附件编号` 或 `【语音】（转写内容）@附件编号`，原文件分别保存在当前人格的图片、语音目录；识别文字与原始媒体分开管理。
- **以共同经历为中心**：记录发生过什么、当时为何重要、后来怎样变化；用户向模型讲述的往事与双方实际参与的交流分开。
- **相关时自然回忆**：当前话题相关时可以提起旧事；不随机闪回，不主动发消息。
- **一个独立个体固定一个人格身份**：软件可管理多个独立个体，各自拥有完整的记忆、上下文和缓存。
- **身份不随运行配置改变**：模型、Mofox 自定义机器人配置、聊天入口和会话均不能取代稳定的 `persona_id`。同一个体与不同用户交流仍需限制私人记录的可见范围。
- **先完成长期记忆闭环**：人格自动成长、自主愿望、独立目标系统、主动行动、多端同步和离线休眠重塑后置。
- **手工资料与程序记忆分开**：每个人格下提供 `users/`，供用户自行存放个性化文件；程序不读取、索引、自动导出或备份其中内容。

开启该实验记忆模式时，界面明确说明会保存双方全文及实际发送的图片、语音附件；不再把“摘要＋关键原话”作为唯一持久记录。关闭记录采用“暂停保存”：仍可读取允许访问的旧记忆，关闭期间的新消息及附件仅用于临时交流，不写入长期记录、摘要、索引、导出或备份；重新开启后不补存，也不能借近期上下文将暂停期间内容带入长期整理。暂停期间上传的文件如需临时缓存，只能留在项目临时目录，使用结束后清理。

遗忘只针对用户选中的对话记录及其直接派生内容，不自动扩展删除其他对话中独立提到的同一件事。选中记录及附件先进入回收站，立即退出日常记忆，保留 7 天后永久清理；支持提前永久清理和到期前恢复。其他独立记录仍可能使同一件事再次被回忆。

## 2. 实验项目与主项目的关系

实验项目建议目录名为 `MemoryLab`，实际名称和位置由建立项目时指定。**创建全新独立 Git 仓库，不从 QQBot 仓库建立分支，不复制完整主项目，也不预设共同版本历史。** 当前阶段只编写本方案，不创建该目录或仓库。

仅提取必要的模型调用、人格范围绑定及本地服务安全机制；先核对依赖和许可，再决定复制还是重写为薄适配。不要带入 QQ、NapCat、Mofox、桌面壳、发行安装器及其默认运行路径。

交接时逐项记录提取文件、源提交编号、纳入的未提交改动、许可和必要依赖。不能只记录一个提交号，却默认未提交修复和未跟踪文档也已包含。此前只读检查得到的主项目 HEAD 为 `8ce8d5f13fea7fa87aa2b74996e5900f43d5c49c`；提取代码时重新核对，不将该编号视为永久最新版本。后续通过版本化接口和适配器接回主项目，而非承诺直接 Git 合并整个仓库。

只迁入必要代码、测试及依赖锁定说明，不复制作者配置、人格、记忆、聊天、登录态、音频、密钥或历史日志。准备干净依赖，不把主项目的 `.local/` 或整个运行目录当作初始化资料复制。

第一版提供简单本地网页，使用合成数据和模拟模型先验证闭环；实际模型测试在明确配置后进行，密钥只保存在内存或受保护凭据机制中。首阶段不启动 QQ，不向真实用户发送测试消息，不使用外部原 Bot 环境。

交付限定为本机实验版：允许首次准备环境和配置模型；以后双击启动，不要求用户每次手动执行命令。不包含干净电脑自动安装、便携发行包、自动更新、远程访问及公网部署。网页、聊天编排和记忆核心先采用单个本地后端进程，后台整理使用受控任务；不把独立记忆微服务部署作为首版前提。

### 3.1 简单本地网页的必要内容

- **聊天**：流式或明确等待状态、停止生成、失败提示、新建及恢复会话；支持图片查看、语音播放及转写状态。流式期间为临时草稿，正常完成后正式保存；主动停止时丢弃草稿。失败重试与新发一条消息分开，避免重复入库；同一问题的两次正常完成回答均保留。
- **历史与来源**：按会话、时间、关键词搜索原文，查看命中原话及前后文；每次回答可展开“本次提供给模型的历史来源”。清单说明实际注入的记录，不宣称能证明模型内部究竟使用了哪一条。
- **记忆管理**：暂停保存开关、纠正、遗忘及处理状态；提供 7 天回收站，显示删除时间、到期时间、所选对话和附件范围，支持恢复及提前永久清理。展示原文与媒体保存状态、转写或描述待处理、片段待索引、摘要失败或已完成等状态，支持重试。
- **基础设置**：人格固定身份、可编辑设定、模型地址和模型选择、连接测试；展示模型调用及 embedding 的本地/远程数据流。首版默认操作一个人格，不为多机器人管理增加复杂界面，核心仍严格隔离身份。
- **数据操作**：按范围导出、手工快照、经校验恢复；`users/` 仅提供打开目录入口，不展示、预览或扫描其内容。

本地后端只监听回环地址，不默认监听局域网；浏览器会话、请求来源校验和修改操作防伪造纳入验收。不能仅因地址是 localhost 就跳过鉴权；聊天正文视为不可信文本，不直接作为 HTML 执行。首版不给模型任意文件访问、终端或自由 SQL 权限。

### 3.2 本机启动与故障边界

首次准备脚本在新项目根目录内建立运行时、依赖及缓存，记录可重复的版本；不改系统 Python、既有 Ollama 或原 Bot 环境。启动脚本显式绑定项目内数据、临时和缓存目录，检查环境和端口，后端就绪后再打开网页；缺少依赖或模型不可用时给出可操作提示，不反复静默重试。

端口冲突不终止未知进程；关闭网页不等于停止后端，提供清晰退出入口，退出只处理本项目创建的进程和任务。无法确认外部模型服务写入位置时，不由启动脚本擅自拉起或接管它。

**本地网页不等于本地推理。** 已确认允许远程模型接收聊天回答和经历整理所需的相关对话；按任务选择必要片段，不默认上传整个记忆库。图片、语音按第 4.6 节的远程输入规则处理，设置页与本次来源清单区分原始媒体、转写、图片描述及实际发送的内容。embedding 仍以本地方案为初始方向，本次确认不改变其配置；远程 embedding 另行明确授权。

新仓库采用中性目录名 `data/memory/metadata.db` 与 `data/indexes/vectors/`，不依赖 Booku 或 Chroma 的路径约定；向量后端由适配层确定，不在方案阶段强行绑定。使用独立表前缀及迁移版本。首版不要求预装数据库服务，也不因为本机已有 PostgreSQL 而增加适配；后续集成在主项目副本中单独迁移，不能直接打开原主项目的数据库试写。切换时只启用一个权威记忆模式，同时处理旧工具和提示词注入路径。

SQLite 的日志及临时产物同样留在项目目录。外部 Ollama、Python 和模型目录只读；准备运行时及服务时先核对其临时、配置和缓存位置，端口独立分配，不接管用户已有服务。公开权重可在各人格之间复用，记忆库、提示词、上下文和检索缓存不可因此共享。

### 4.1 `users/`：用户手工管理的个性化文件库

`users/` 位于当前人格目录下，避免不同人格的手工资料混放。用户可以自行建立子目录、存放笔记、文档和其他个性化文件；图中的文件名只作示例，不要求程序生成这些文件。`<user_id>` 是人工整理目录的示意，不替代数据库中的用户身份和访问范围。

- 程序可在创建人格时建立空 `users/`，或提供打开该目录的入口；不枚举其文件、不打开正文、不生成摘要、哈希或向量，也不监视文件变动。
- 记忆检索、模型文件工具、通用知识库扫描、调试打包、导出和备份都排除 `users/`。从候选路径开始排除，不能先读文件再决定不用；其他可读目录中的链接也不能绕过这一边界。
- 文件内容不会因放入 `users/` 而成为人格设定、用户事实或模型知识，程序也不自动把数据库中的个人资料写回这里。
- 用户在聊天中自行粘贴某段文字时，该文字作为本轮消息处理；这不授权程序打开原文件或读取同目录其他内容。
- 文件由用户手工维护和备份。清空记忆、恢复快照或删除人格时，程序只处理受管数据白名单，保留 `users/`，不能递归删除整个人格根目录并连带清除手工文件。

因此，“程序不读”也意味着程序不能替它自动备份。需要保留这些文件时，由用户使用文件管理器自行复制；这部分不计入记忆系统的数据恢复承诺。

### 4.2 四层记忆分别存放在哪里

四层是职责划分，不要求四个互不关联的文件夹。同一份 SQLite 可以保存原文、摘要和它们的关联，避免多份正文相互覆盖。下表中的表名是目标设计，尚未创建。

| 层次 | 物理位置 | 读取与恢复方式 |
|---|---|---|
| 1. 固定人格与规则 | `manifest.json`、`editor.json`、`lore/` 为编辑源，编译为 `system.md`；版本放入 `generated/persona-version.json` | 每轮使用当前人格设定理解历史，保留当前版本标识核对编辑源与产物；历史原话不改写，不要求关联历次人格版本参与回忆 |
| 2. 近期上下文 | 主要在当前人格、当前会话的进程内存中；持久原消息在 `metadata.db` 的 `ltm_messages`；可选 `context/<session_id>/` 仅缓存游标和消息编号 | 重启后从数据库恢复允许读取的近期消息，不再维护第二份完整对话；长聊接续摘要关联来源消息 |
| 3. 完整消息记录 | `data/memory/metadata.db` 的 `ltm_messages`，以及附件、来源、修订、范围和回收站等相关表；原始媒体位于 `data/media/images/`、`data/media/audio/` | 双方每条原消息按编号、会话和时间读取，附件按稳定编号展开；原文、媒体及其对应关系不能仅凭摘要补回 |
| 4. 经历摘要与检索索引 | 经历在同库 `ltm_episodes`，长聊接续摘要在 `ltm_session_summaries`，片段在 `ltm_chunks`；全文索引在同库 `ltm_messages_fts`，向量在 `data/indexes/vectors/<index_generation>/` | 摘要和片段关联原消息；检索命中后回查数据库；派生索引可重建，不能决定原文真假或归属 |

`users/` 不属于四层中的任何一层。由程序读取的人格扩展资料放在明确的 `lore/`，手工留存而不让程序读取的资料放在 `users/`；二者不能因为内容相似而自动同步。

### 4.3 `exports/`：按需生成、供人阅读或另存的副本

导出由本机用户显式发起，选择当前会话、日期范围或指定经历；默认当前会话，不默认导出全部用户的历史。访问范围在导出时重新核对，不因导出而扩大。每次建立新的 `<export_id>` 子目录，避免覆盖上次结果。

可选内容如下，只有用户选择的格式和内容才生成：

| 导出内容 | 示例文件 | 包含什么 |
|---|---|---|
| 可读对话 | `transcript.md` 或 `transcript.txt` | 选择范围内的双方原话、说话者、时间和消息 ID；可说明关联的纠正状态 |
| 结构化消息 | `messages.jsonl` | 同一选择范围的逐条记录、必要来源和版本信息，便于外部处理 |
| 经历阅读版 | `episodes.md` | 选择的经历摘要、时间、参与者、关联消息 ID；可选附上有权限的原话 |
| 人格阅读版 | `persona.md` | 当前人格编辑源的可读呈现及版本说明；仅在明确选择时生成 |
| 本次导出说明 | `export-manifest.json` | 导出时间、所属人格、选择范围、格式版本、记录数和文件清单 |

导出不含 `users/`、其他人格、范围外私聊、密钥、QQ 登录态、缓存、向量库或完整数据库。已删除内容不能导出；被纠正的历史发言如被选择，应标注原话与纠正的关系，不能冒充当前事实。导出前检查当前已知密钥，按既有保护规则拒绝或脱敏，不能借“原文导出”泄露凭据。

导出是某一时刻的副本，不随数据库纠错自动改写，也不自动反向导入或索引。本次实验不提供把普通导出作为完整恢复包的功能。

文本导出保留图片、语音类型标记、附件 ID 和可用的识别文字，并注明是否附带原文件。只有用户选择“包含附件”时，才复制范围内有权限且未入回收站的原始媒体，并生成导出包内的相对链接与对应清单；仅文本导出不能伪装为已包含媒体。导出不写入本机绝对路径或带会话凭据的内部下载地址。程序管理的导出附件同样纳入来源删除追踪。

程序管理的 `exports/` 纳入删除范围追踪：保存导出文件与来源消息的关联，相关消息被删除时使对应导出失效并移除或重新生成，不能保留被删正文。用户已经自行复制、移动到其他位置或分享出去的副本不在自动清理范围内，生成时说明这一点。程序不为了查找副本去扫描 `users/`。

### 4.4 `backups/`：“本人格备份”指这个个体的可恢复快照

这里的“人格”指独立个体，因此快照既包含其人格编辑源，也包含其程序管理的完整记忆，不只是几句性格设定。它用于误操作、数据损坏或升级失败后的恢复，不参与模型日常检索。

```text
backups/<snapshot_id>/
├─ snapshot.json                    # 人格 ID、时间、数据版本、文件清单与摘要
├─ persona/
│  ├─ manifest.json                 # 人格身份和基础设定
│  ├─ editor.json                   # 补充设定
│  └─ lore/                        # 程序管理的人格扩展源
├─ memory/
│  └─ metadata.db                   # 一致性快照：消息、附件、来源、修订及回收站状态
├─ media/
│  ├─ images/                       # 快照内消息引用的图片原文件
│  └─ audio/                        # 快照内消息引用的语音原文件
└─ index-config.json               # 模型摘要、维度及处理版本；用于重建索引
```

- 只按白名单备份当前人格的受管数据，不递归复制整个人格目录。排除 `users/`、`exports/`、已有 `backups/`、其他人格、密钥、登录态、日志和临时缓存。
- 第一版默认不备份向量库和生成的 `system.md`：从权威库重建索引，从人格源重新编译提示词；用户后续确认过的修订及其依据已经包含在数据库快照中。
- SQLite 使用一致性快照流程；不能直接复制正在写入的单个 `.db` 文件就宣称备份完整。快照同时收集该数据库视图引用的受管媒体，记录附件 ID、相对路径、大小及校验摘要；复制期间固定文件可用性并校验，避免只备份引用而缺少原文件。恢复清单记录数据库、媒体清单及人格源对应的版本。
- 恢复先在独立项目内目录校验数据库、附件清单、文件完整性及引用范围，并应用快照创建后已经发生的回收站、恢复及永久删除状态；核对完成再显式切换，不自动覆盖正在运行的数据。原人格身份及附件 ID 保持连续，不与另一个人格合并。当前有效的生命周期清单必须独立于待回滚的快照保存，不能仅用旧快照内的删除状态代替；缺少最新清单时不能宣称已满足防复活校验。
- 删除后的临时保留统一使用 7 天回收站，不再以“旧备份残留”承担恢复入口。快照中仍含相关对话或媒体时，同样受当前回收站状态及原到期时间约束；恢复旧快照不重置 7 天期限，不使回收站内容恢复为日常可读。到期或提前永久清理时，一并移除受管快照中的对应内容，或移除无法安全清理的受影响快照；界面明确相应恢复点失效情况。
- 第一版支持手工创建快照和升级前快照；定时备份后置。向量与摘要正常后台整理不等于创建备份。

### 4.5 文件的权威关系

| 文件或内容 | 性质与规则 |
|---|---|
| `manifest.json`、`editor.json`、用户编写的 `lore/` | 人格编辑源；各字段有明确权属 |
| `users/` | 人工文件库，不参与读取、检索、导出、备份或程序自动清理 |
| `system.md`、`persona-version.json` | 人格编译产物，可由编辑源重新生成 |
| `metadata.db` 中的原始消息、附件关联、修订、范围、回收站状态与来源关系 | 权威数据，不能仅凭摘要或向量重新制造 |
| `data/media/images/`、`data/media/audio/` | 程序管理的原始媒体，按附件 ID 关联消息；参与回收站和一致性快照，不属于 `users/` |
| 语音转写、图片描述等识别结果 | 带附件来源和处理版本的派生内容，可能有错，可修正；不覆盖原始媒体，不冒充用户实际输入的文字 |
| `metadata.db` 中的全文索引、片段及经历摘要 | 派生内容，可在来源与权限允许时重建；用户手工确认的修订及其依据另行保留 |
| `indexes/`、`context/`、`cache/` | 派生索引或状态，不可绕过权威库校验 |
| `exports/` 中的 TXT、MD、JSONL 等 | 选择范围的副本，不是恢复点或编辑源；程序内副本受来源删除追踪约束 |
| `backups/` | 当前人格受管数据的恢复点，不含 `users/`；不参与日常召回，恢复先应用当前撤回及删除清单 |

不要求为每条消息建立一个 Markdown 文件；逐条原文存入 SQLite。若用户需要可读文件，生成带时间和版本的导出。以后新增原始资料导入时，独立定义来源分类，不能把模型生成的导出当作新独立证据自动导回。

### 4.6 图片、语音与稳定附件引用

双方实际发送的图片与语音均作为消息附件管理。聊天记录可显示为 `【图片】@att_<完整ID>`，或 `【语音】（转写内容）@att_<完整ID>`；未转写时显示“尚未转写”，失败时显示处理状态并允许重试。图片描述单独标为识别结果；原始语音、语音转写、图片描述和经历摘要保留各自来源及版本，修改识别结果不修改原始媒体。

每个附件接收成功时分配一次随机稳定 `attachment_id`，由数据库唯一约束保证不重复，并记录所属人格、消息 ID、类型、项目内相对路径、大小、可用时的媒体时长及处理状态。可采用 `att_` 加完整 UUID 的格式；界面可缩写显示，内部关联与点击请求使用完整 ID，不靠缩写定位。

编号代表这一次附件记录，不是文件夹路径、日期序号或文件内容摘要。移动整个项目、切换模型、重启、备份恢复和从回收站恢复均不改变它；同一提交重试复用原附件记录，用户另发一次相同文件则建立新的消息及附件记录，不因文件内容相同而合并两次发言。页面显示名称可以变化，不影响稳定 ID。

点击 `@附件编号` 时，由本地后端按完整编号查询元数据，复核当前人格、用户权限及回收站状态后查看或播放。编号不是访问授权；不允许把任意文件路径拼进链接，也不借附件读取接口访问 `users/` 或项目外路径。普通聊天入口不能读取回收站附件，仅有权限的回收站管理入口可查看及恢复。

媒体三条规则如下：

1. **回收站**：遗忘选中的对话时，关联附件及识别结果一同退出正常使用，原文件随所选记录保留在 7 天回收站范围内；立即使相关摘要、向量、缓存、当前上下文及受管导出失效，混合其他消息的派生内容只用仍有效来源重新生成。不删除其他对话中独立存在的记录。从回收站恢复时恢复原消息—附件关联和稳定 ID，并重建必要索引；到期或提前永久清理时，清理原文件、识别文字及受管副本。
2. **备份**：一致性快照必须包含快照内有效消息及尚未到期回收站记录所引用的图片、语音原文件和对应清单，不能只保存数据库与文字链接。校验文件与引用一致后才允许恢复，并应用最新回收站及永久删除状态；已到期或已永久删除的媒体不能从旧快照复活。始终排除 `users/`、暂停保存期间内容及未提交草稿。
3. **远程输入**：已确认允许为聊天回答和经历整理向配置的远程模型提供必要的相关对话。对图片、语音，纯 `@附件编号` 或本机文件路径不能替代实际输入：适配层仅在模型支持时，按受限附件 ID 读取并发送任务需要的原始媒体；只接受文字的模型使用明确标注的转写或图片描述，必要识别能力不可用时显示未识别，不伪称模型已经看过或听过。来源清单记录此次实际发送的是原文件、识别文字还是二者；不因此赋予模型浏览本机目录的权限，不默认上传整个媒体目录，也不改变本地 embedding 的安排。本机回收站只能管理本项目的数据，不能承诺撤回远程服务已接收的内容。

### 4.7 仅遗忘所选对话与 7 天回收站

回收站首先是数据库中的消息、附件状态及其关联，不要求再建立第三套媒体文件夹，也不为了删除额外复制媒体。原文件可以继续留在受管媒体目录，由状态及后端权限隔离；只修改网页显示而后台仍可检索不算完成遗忘。

保留期限从本次移入回收站开始计算 7×24 小时，界面显示进入时间和到期时间。恢复旧快照不延长期限；到期前用户主动恢复后，再次主动遗忘属于新的操作。提供按项恢复、按项永久清理和清空回收站。软件未运行时无法执行到期清理，下次启动必须先屏蔽到期内容并安排清理；未清完时展示待清理或失败状态，不声称已经彻底清除。

回收站及永久删除状态同时约束消息搜索、前后文展开、摘要、向量、模型注入、当前上下文、媒体接口、导出、后台任务和快照恢复。遗忘时取消或使相关在途任务失效，迟到结果不能重新写回可用状态。最新生命周期清单包含必要对象编号、操作序号及时间，不保留已经永久清理的正文和原文件；恢复数据时不能回滚该清单。

纠正仍与遗忘分开：例如保留“我住北京”的原话并关联“那天说错了，我一直住上海”，日常事实采用纠正，查历史仍能核对原话。不同时间的有效变化按已知事件时间理解；允许自动整理而不要求每次经用户确认，仍须区分原话、变化和模型推断。

## 5. 数据对象、编号与接口

### 核心对象

| 对象 | 必要内容 |
|---|---|
| 消息 | 内部整数主键、随机消息 ID、人格、说话者、会话及顺序、时间、完整正文、附件关联、来源编号、可见范围及状态 |
| 附件 | 稳定随机附件 ID、消息 ID、人格、媒体类型、受管相对路径、大小、可用时的时长、识别结果关联及回收站状态 |
| 媒体识别结果 | 来源附件 ID、转写或图片描述、处理模型与版本、失败及修正状态；与用户原话分开 |
| 回收站操作 | 操作编号、所选消息及附件范围、进入和到期时间、恢复或永久清理状态及最新操作序号 |
| 片段 | 一组连续原消息的关联、片段正文或可重建范围、来源版本、向量索引版本 |
| 经历 | 事件经过、参与者、已知事件时间、关联原消息与片段、摘要版本；未知时间明确留空 |
| 修订与变化 | 对应对象、原因、适用时间、前后关系；区分过去真实成立与原记录错误 |
| 索引任务 | 人格、运行代号、对象编号及版本、模型摘要、处理及索引版本、操作与重试状态 |

相同正文的两次真实发言分配不同随机消息 ID；同一平台消息重投或同一写入请求重试，应使用来源标识或幂等键识别，避免制造重复事件。随机 ID 不承担时间排序，前后文用同会话顺序定位。

### 最小核心接口

下列名称是目标接口，不表示现有代码已经提供：

| 接口 | 行为 |
|---|---|
| `record_message(scope, message, idempotency_key)` | 保存单条消息及全文索引，返回稳定消息 ID；模型失败不回滚已经接收的用户消息 |
| `search_messages(scope, query, filters, limit, cursor)` | 直接搜索原文，返回消息 ID、说话者、时间、片段及受限分页结果 |
| `read_messages(scope, message_ids, before, after)` | 按编号展开原文及相同会话的有限前后文，逐条复核可见范围 |
| `search_episodes(scope, query, filters, limit)` | 查找经历及其原消息关联，不成为读原文的唯一入口 |
| `correct_memory(scope, target, correction)` | 建立有来源的纠正或状态变化，保留正确的历史语义 |
| `delete_memory(scope, target)` | 将选定对话及关联附件移入 7 天回收站，立即使相关派生内容失效，返回范围、到期时间及处理状态；不自动扩展到其他独立对话 |
| `restore_memory(scope, recycle_item_id)` | 在到期前恢复消息与附件关联，保留原编号，重建必要派生内容并记录新的生命周期状态 |
| `purge_memory(scope, recycle_item_id)` | 提前或到期永久清理所选原文、附件与受管副本，保留不含正文的必要防复活状态；未清完时不声称已经全部清除 |
| `read_attachment(scope, attachment_id)` | 按稳定编号校验归属、访问范围和状态后查看或播放媒体，不接受任意文件路径；回收站读取走受限管理入口 |

`scope` 由宿主程序绑定人格、用户、会话及运行代号，模型只能提交该范围内的搜索条件，不能传入任意目录或扩大身份范围。用户界面与模型工具使用同一套受限服务。

## 6. 写入、检索与整理

```text
接收用户消息 → 保存原文及全文索引 → 查询相关历史 → 生成模型回答
                                                   ↓
                                  正常完成后保存回答；主动停止丢弃草稿
                                                   ↓
                                  后台更新片段向量与经历摘要
```

模型回复失败或中断时明确记录请求状态，不伪造完整回复；未完成草稿不作为正式发言进入历史、上下文或回忆，已经接收并保存的用户消息仍保留。近期消息在后台向量未就绪时仍可通过原文和近期上下文读取。

记录与基础检索由程序编排，不能依赖模型是否愿意调用记忆工具。接收用户消息先持久化，成功后界面才标记“已保存”；写入失败时明确提示，不显示为已记住。媒体消息需先完成受管文件写入及校验，再提交消息—附件关联；失败时显示未保存状态并清理无归属的临时文件，不生成指向缺失媒体的成功记录。

助手流式显示期间作为临时草稿，不写入正式消息库、全文或向量索引、摘要、导出及备份；正常完成后一次提交正式回答，再确认保存状态。主动停止、生成失败或被取消的未完成草稿丢弃，仅保留不含草稿正文的必要请求状态。浏览器断开不自动等同于主动停止：后端正常完成并提交的回答可在重连后读取，尚未完成就退出或崩溃则草稿不恢复为正式发言。生成中的图片或语音同样按草稿处理，取消时清理临时媒体。同一问题的两次正常完成回答分别保留并关联请求；传输重试不制造重复回答。

```text
当前人格、用户与会话范围
         ↓
近期上下文 + 问题类别与时间条件
         ↓
结构化查询 / 原文全文检索 / 片段向量 / 经历摘要
         ↓
合并候选，按消息编号展开必要原文
         ↓
核对说话者、时间、权限、纠正与删除状态
         ↓
按预算提供给模型，保留可展开的来源
```

- 原文全文索引与消息事务同步提交，摘要及向量异步生成。失败任务可重试，旧任务完成不能覆盖新版本或复活已删除正文。
- 中文短名字、原话片段和编号采用适合的词项及字符索引，命中后核对原文；不能假定默认英文分词已经满足要求。
- 摘要关联原消息编号或范围，不作为新的独立证据。用户说过某件事、模型推断某件事和共同完成某件事分别表达。
- 当前问题可以直接查原文，或先查经历再展开；初次未命中可按预算扩大查询，不把一次没找到说成用户从未提过。
- 原文全部保留，每轮只加载有限候选及前后文；旧事件仍可进入检索，不默认限制为最近一个月。
- embedding 不可用时保留受限的全文及结构化查询。切换人格时取消旧请求与后台任务，拒绝迟到写入和发送。
- 首先保留可替换的 BGE-M3 embedding 方案，用固定用例和耗时测量决定是否更换，不因名称或新旧直接认定更优。完整消息逐条保存，向量针对有来源关联的连续片段生成，不要求每个“嗯”独立计算向量；换模型使用新索引代，不能混查不同维度和版本。
- 整理增量处理新增和被修订的片段，不每轮重新扫描或改写全库；限制候选数、扩展次数、上下文 token 和后台并发。记录不设重要性淘汰，不等于每轮把全部历史塞给模型。
- “每条保存”是默认对话保留规则，不覆盖用户明确关闭记录、显式删除及凭据保护。界面提醒不要发送密钥；已识别凭据在落盘前拒绝或脱敏并标记，不能声称已可靠识别所有秘密。聊天记录作为资料而非系统指令，历史原话中的命令不得提升为人格规则。

### 6.1 本地模型的职责与准备边界

本次讨论采用“本地保存与检索、远程聊天与经历整理”的职责安排：

| 工作 | 首版安排 |
|---|---|
| 原话、媒体、权限、纠正、回收站、时间与关键词查询 | 本地程序、数据库及受管媒体目录负责 |
| 按意思寻找相关对话 | 本地 embedding；先保留可替换的 BGE-M3 方案 |
| 根据所选历史组织回答、整理经历摘要 | 允许配置的远程模型接收必要的相关输入 |
| 图片或语音识别 | 保留适配入口，具体服务、模型及输入格式实施前确定；不能把“本地 embedding”当作已具备看图、听音频的能力 |

本地 embedding 在本项目中的任务是对文字片段及查询生成用于相似检索的表示，不承担聊天回答。以已有公开模型推理，不把新增聊天用于训练或改写模型权重；个人记忆保存在消息、媒体、识别结果及派生索引中。找到的候选仍须回查原消息，不能把语义相似当作事实核实。

首版不要求先安装本地聊天大模型，也不将 Ollama 作为必需前提；具体 embedding 加载方式和依赖应独立准备。公开模型权重放入项目 `.local/caches/models/`，运行环境放入 `.local/runtime/`，不占用 `users/`，不修改已有 Ollama 或原 Bot 环境。

准备步骤应列出必要文件、模型版本、下载量及磁盘需求，实际资源需求以锁定版本和本机测量为准，不把单个权重文件大小当作安装总量或内存需求。运行实现可按所选依赖支持情况采用 CPU 或兼容 GPU；本机硬件尚未核对，不承诺固定速度、显存或内存门槛。限制批量、片段长度和后台并发，测量后确定默认值。

准备完成后，运行时应能仅加载项目内已有模型文件，不依赖每次启动重新下载。断网时本地历史查看与已就绪检索仍可用；远程回答、经历整理或远程媒体识别显示连接不可用，待恢复后处理。embedding 暂不可用时仍保留原文、受限全文及结构化搜索。

## 7. 实施阶段与验收

| 阶段 | 交付与验收 |
|---|---|
| 0. 独立启动与网页壳 | 新仓库不依赖 QQBot 运行目录；一次准备后双击启动网页；回环限制与请求保护有效；端口冲突不影响用户已有进程 |
| 1. 完整记录 | 双方逐条保存；重复正文不合并、请求重试不重复入库；重启后按编号读取；模型失败仍保留已经接收的用户消息 |
| 2. 原文入口 | 中文短名字、编号、词句、人物和时间可搜索；按消息编号展开前后文；跨人格及用户私聊读取被拒绝 |
| 3. 经历与语义 | 片段关联全部来源消息；摘要遗漏的信息可从原文独立找到；模型回复不成为现实事实证据；相关话题可自然回忆 |
| 4. 纠错与一致性 | 区分历史变化、原记录错误、文字修订与回收站；只遗忘所选对话，7 天内可恢复，到期或提前永久清理；旧任务、缓存、当前上下文、重启和恢复均不能绕过状态 |
| 4a. 手工文件与文件副本边界 | 在 `users/` 放置合成文件，读取、检索、导出、备份与诊断流程均不打开它们；链接不能绕过排除；清空记忆或删除人格保留手工文件；导出范围和来源删除追踪有效 |
| 4b. 导出与快照恢复 | 对话、经历和人格阅读版各按选择生成且不自动导回；媒体导出明确是否含原文件；快照同时校验数据库、媒体及最新生命周期状态，恢复保持人格和附件 ID 连续，不重置回收站期限 |
| 4c. 网页闭环与诊断 | 网页能聊天、恢复会话、搜索并展开原文、纠错和删除；展示实际注入来源和索引状态；回复失败不丢用户消息；刷新、重复提交和后台失败不制造重复或跨范围记录 |
| 4d. 图片与语音 | 用合成媒体验证类型标记、转写与原文件分离、稳定附件引用、移动项目及重试、受限查看播放、回收站恢复与到期、快照文件完整性；模拟远程适配验证实际发送内容及不支持输入时的提示，不用本机路径冒充媒体输入 |
| 5. 首版对照交付 | 固定用例对照和规模测试，提供启动说明、依赖锁定、接口及数据格式说明；接 QQBot 不作为首版完成的前置条件 |

规模测试使用 1万、10万、100万条合成消息，分别记录数据完整性、召回质量、错误归属、检索耗时、内存、索引积压及模型调用成本。检索耗时与模型回答耗时分开，测试前记录机器配置、索引设置及验收门槛；未执行或未通过的项目明确列出，不用模型恰好回答正确替代来源验证。

### 7.1 本轮讨论明确留待后续确定的事项

- 用户个人最关注的三到五个记忆问题及对应验收样例，已明确“以后再说”，本轮不代为选定。已有合成验证和规模测试框架继续保留。
- 实验项目的实际名称和路径、聊天及经历整理所用的远程服务地址和模型、本地 embedding 的最终版本与运行依赖，以及本机资源配置和性能门槛，尚未最终配置或验证。
- 图片、语音识别的具体模型或服务、支持格式及大小和时长限制，尚未选定；已确定的是消息显示、原文件目录、稳定编号、识别结果与原始媒体分离，以及回收站、快照和远程输入规则。

本方案整理讨论中已确认的功能选择与必要解释，不是逐字聊天实录；举例中的人名、地点、话语和附件编号不作为真实用户资料导入。早先提出的“忘掉一件事并扩展删除其他对话”已被最新确认的“仅遗忘所选对话”取代；“旧备份残留保留 7 天”已被 7 天回收站取代。

## 8. 后续适配接回主项目

实验交付包括记忆核心、简单网页、启动脚本、模型薄适配层、合成测试、接口和存储说明、对照结果，以及未来集成的迁移和回退约定。独立仓库与主项目不要求共同 Git 历史；以后按版本引入核心包或审查复制必要源码，并编写 QQBot 宿主适配。不要整体覆盖主项目，也不迁入实验数据库、人格、聊天、缓存、模型权重或运行状态。

接入主项目前，用明确开关在副本中验证新旧记忆模式只能有一个生效。真实旧数据迁移另行核对版本、来源和范围；无可靠归属的数据不自动提升为当前事实。模式或索引回退仍应用当前撤回及删除状态，不能让旧数据重新可读。

本次仅生成交接文档及文档入口，未创建实验项目、未实现上述模块、未启动服务、未迁移任何用户数据。总体设计可参考同目录的《记忆与人格结构优化方案》v0.2；涉及保存粒度和首版范围时，以本文最新确认的“双方逐条全文保存、反思和愿望后置”为准。
