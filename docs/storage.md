# 存储、生命周期与恢复

原文、附件引用、修订、请求状态、来源关系、任务、片段、经历和产品登记在每个人格 `data/memory/metadata.db`。使用 SQLite WAL、FULL 同步、内存临时表及 secure_delete。FTS 使用编码后的中文单字、双字和西文词项；查询回核原文，避免将近似匹配冒充原话。

人格源为 `manifest.json`、`editor.json` 和 `lore/*.md`。`system.md` 与版本摘要可重建。`users/` 只创建空目录和打开入口；所有遍历都从受管白名单子目录开始，路径保护拒绝符号链接、Windows 目录联接、越界和任何大小写的 `users` 路径段。

生命周期清单位于 DATA_ROOT 下 `lifecycle/<persona_id>.db`，包含独立身份和递增操作序号，不包含消息正文。它不在快照替换范围内。操作先写意图，再应用权威库，最后确认；每次读写前及启动时重放未应用状态。已有数据库缺少清单、清单身份不符或清单比数据库旧时拒绝打开。

回收站期限为 7×24 小时，启动及读取前处理到期操作。恢复不改变消息、附件 ID；主动恢复后重新遗忘才产生新的到期时间。删除立即屏蔽原文、媒体和派生来源；旧后台任务按 epoch、运行代号、来源 revision 和生命周期序号拒绝提交。受管导出立即失效并移除，旧快照保留且受当前清单约束。

永久清理移除原始媒体、识别文字、修订、失效派生内容、向量分代及受影响快照，整理 FTS、压缩数据库并截断 WAL。只保留必要编号、状态和操作时间。不承诺 SSD、文件系统快照、系统备份、用户自行复制副本或远程服务中的取证级擦除。

快照使用 SQLite Backup API，在本机进程锁内固定写入和媒体清理，复制消息引用的媒体与人格源并登记大小、摘要。向量无需备份，恢复后重建。快照不包含 users、密钥、日志、临时文件或已有快照。

恢复先校验身份、数据库结构、完整性、文件清单、媒体引用和最新生命周期清单；在独立暂存目录准备，再持久记录恢复意图后切换。中断恢复在下次打开库之前重放。暂存目录在生命周期重放成功后清理。快照之后的新消息不属于恢复结果；恢复不是历史合并。恢复过程中不自动创建新的恢复点，操作前可另建手工快照。

schema v1 的附加 `payload_hash` 列通过幂等迁移建立，用于校验请求内容一致性。后续不兼容升级必须增加显式版本迁移，禁止直接打开原 Bot 数据库试写。
